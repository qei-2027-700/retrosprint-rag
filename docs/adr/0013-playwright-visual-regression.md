# ADR-0013: ビジュアル回帰テストをPlaywright公式イメージで実行する

- 決定日：2026年11月5日
- 状態：accepted
- 関連：[Issue #16](https://github.com/qei-2027-700/retrosprint-rag/issues/16)

## 背景

既存のE2Eは画面を撮影するが、正解画像との比較は行わない。ホストOSやフォントが違うと、同じ画面でも画像差分が生じる。

## 決定

月の振り返りの回答画面と引用元2件を、PC・SPで `toHaveScreenshot()` により比較する。正解画像をGitで管理する。Playwright 1.64.1の公式Ubuntu NobleイメージをLinux amd64でローカルとCIに共用し、`@playwright/test` も1.64.1に固定する。撮影時だけ確認日時を固定する。差分の許容閾値は設けない。

既存の機能E2Eと調査用スクリーンショットは維持する。ビジュアル比較はDocker内で追加実行し、CIは正解画像を更新しない。正解画像を変える場合は開発者が差分を確認してコミットする。

## 理由と影響

画像比較の実行環境と正解画像の生成環境を揃えられる。正解画像はartifactの保存期限に左右されない。一方、ローカル実行にはDockerが必要で、CIの実行時間と保存するPNGが増える。機能E2Eの撮影画像は失敗時の調査に使い、正解画像とは分ける。

## 検証と再検討

同じコミットでローカルとCIの画像比較を実行し、意図的な画面変更で失敗とdiff画像の保存を確認する。ブラウザやPlaywrightの版を上げるときは、公式イメージと依存を同時に更新し、正解画像をレビューする。Docker実行時間が継続的な検証を妨げる場合は、同じ撮影条件を維持できる別の実行方法を検討する。
