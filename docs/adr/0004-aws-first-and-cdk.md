# ADR-0004: AWS先行とAWS CDKの採用

- 決定日：2026年10月12日
- 記録日：2026年10月18日
- 状態：accepted（採用済み。実装・実環境検証は未完了）
- 関連：[開発計画 #1](https://github.com/qei-2027-700/retrosprint-rag/issues/1)

## 背景

この個人開発ではRAGアプリを作るとともに、業務でも活用するAWSの理解とAWS CDKの習熟を進めたい。最初に利用するクラウドを決め、実装・権限・デプロイ・費用管理を具体的に検証できる状態にする。

将来、別のクラウドを検討する余地は残す。repositoryのinterfaceと具体実装を分離する方針を維持し、backendの詳細なディレクトリ構造は実装時に決める。

## 選択肢

| 選択肢 | 判断 |
| --- | --- |
| AWSで先に実装する | AWSとCDKを学ぶ目的に合う。AWS固有の認証・権限・制限・費用を確認する必要がある |
| AWSとGoogle Cloudを比較し、実装直前に決める | 構成や費用を比較できるが、AWSの習熟を優先する今回の進め方とは合わない |
| 両クラウドへ同時に実装する | 比較できる一方、実装・運用・検証対象と費用が増える |

## 決定と理由

初期クラウドをAWS、IaCをAWS CDK / TypeScriptとする。2026年10月12日の本人指定に基づき、AWSとCDKの習熟を優先する。最安のクラウドであると実証したことや、性能比較で優位と判定したことを採用理由にはしない。

回答生成・embeddingにAmazon Bedrock、ベクトル保存・類似検索にS3 Vectors、認証にCognitoを利用する採用方針と合わせて進める。サービスごとの選定理由・接続方式・検証結果は必要な段階で別の判断として記録する。

Lambda、DynamoDB、SQS等の具体基盤、リージョン、モデル・embedding次元、予算・利用枠はこのADRでは確定しない。初期にGoogle Cloud adapterや両クラウドへの同時デプロイは実装しない。

`go-drive-etl` のBigQuery成果物を利用する計画は維持する。BigQueryの直接参照、AWSへの取り込み、用途別併用は、認証・更新削除・出典・越境転送・費用を比較して別途決める。

## 影響とトレードオフ

AWSの実サービスとCDKを使い、RAG、認証、権限、停止・削除、費用管理を検証する。初期に未使用のadapterや全クラウド共通の基盤を作り込まない。

interfaceを分離しても、クラウド移行にはadapter・設定・実行入口・IaCの変更が必要となる。データ変換、利用者IDと認証、IAM、配送保証、更新削除の整合性も確認する。モデル変更時は品質評価や再embeddingが必要になる場合がある。

費用はモデル・リージョン・利用量を決めて再見積もりする。この決定を、予算の承認やデプロイ・課金開始の指示とは扱わない。

## 検証方法と現在の結果

文書上の採用判断を記録した段階。アプリ・CDK・AWS接続の検証完了は未確認。

実装時にはinterfaceを使ったfakeテスト、外部接続の契約テスト、CDK synthとIAMレビュー、AWS接続、RAG品質・遅延・費用を確認する。fakeの成功と実環境の確認結果を分けて記録する。

## 再検討条件

AWSの制約・費用が要件を満たせない場合、学習目的が変わった場合、別クラウドへ移行する具体的な要件が生じた場合に再検討する。継続費・移行費・品質・運用負担を比較し、新しいADRから本ADRを置き換える。

## 根拠

2026年10月12日の本人指定と、その時点のAWS先行の判断記録を引き継いだ。元のADR番号0004を維持し、このリポジトリでのbackend詳細構造を未確定とする方針を反映した。
