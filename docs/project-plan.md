## 参照先と現在地

目的・利用者・採用技術・実装状況は [README](../README.md)、配置・API契約・評価コードの方針は [リポジトリ構成](architecture/repository-layout.md)、重要な技術判断は [ADR](adr/README.md) を参照する。仕様はdocs、作業と検証結果はIssue・PR・CIで管理する。2026年10月12日の `planning/` 内の3文書は検討履歴であり、現行方針と競合する記述は採用しない。

BE・FEの疎通、OpenAPI型生成、通常CI、BEの開発用Composeは実装済み。業務機能、DB・AWS接続、CDK・デプロイは未実装。AWSアカウントは未作成のため、当面は公開可能な合成資料とfakeを使い、ローカルでAPIからFEまでの質問・回答・出典表示を実装する。fakeの動作確認を実際の検索・モデルの品質検証として扱わない。

AWS先行・CDK・Bedrock・S3 Vectors・Cognitoの採用方針は維持する。React/Vite・Gemini、GCPへの全面移行やGCP adapterの同時実装は初期要件にしない。LangChainはBedrock接続・文書分割に限定する案があり、LangGraph・LangSmith・SSEは必須にしない。

## 最終的な必須機能

1. Cognitoのログイン・ログアウト、API認証、admin/userの認可。両ロールとも他ユーザーの会話・メッセージ・ジョブにアクセスできない。
2. 初期は管理者がMarkdown・テキスト・テキスト抽出可能なPDFを登録し、進捗・取り込み状態・失敗理由を確認できる。文書一覧、カテゴリ、原文確認、再試行・削除を扱う。
3. 文書検索に基づく回答と、文書名・版・ページまたは見出し・引用箇所を表示する。根拠不足を明示し、根拠のない事実を履歴から補わない。
4. 複数ターンの会話、会話一覧、再表示・継続・削除を実装する。生成中や障害時も再読み込み後に状態を取得できる。
5. 採用したETL連携経路で取得・更新・削除・出典表示を確認する。認可、競合、利用上限、品質・費用の検証結果を残す。

退会は仕様化の対象として削除範囲・保持期間・処理中と失敗時の扱い・保持例外を決める。詳細と月末版への収録は未確定。音声、OCR、Office文書、エージェント、複数embeddingモデルは初期対象外。

機能specはログイン・ログアウト、チャット回答、資料取り込み、会話履歴、退会など、利用者ができることで分類する。各specに範囲、権限、正常動作、状態への影響、エラー・制限、受入条件、未決事項を記載する。重要な判断のADRには背景・選択肢・決定理由・影響・検証・再検討条件を残す。acceptedは実装検証完了を意味しない。

品質評価は `backend/evaluations/` に置き、本体と同じ検索処理を使う方針とする。標準RAG設定・promptはbackendのresources、実験条件・合成datasetはevaluationsで管理する。生の結果は原則Git対象外とし、共有する小さな報告は必要に応じて `evaluations/reports/` に残す。導入前に空の雛形を一括作成しない。

## ETL連携の条件

`go-drive-etl` は取得・加工・ロード、アプリは検索・回答・画面を担当する。BigQueryの `etl_gold.reflection_documents` の文書単位の最新本文、`file_id`、`document_name`、`drive_url`、`content_version`、`reflection_month`、取り込み日時などを契約として扱い、集計表やCSVを本文の代わりにしない。

AWSからBigQueryを直接参照、AWS側への文書取り込み、用途別併用を比較してADRで決める。認証、NULL、更新・再取り込み・重複・削除、出典、元データの保持期限、越境転送、費用を評価する。通常Viewが永続コピーを保持するとは扱わない。Google Cloud認証情報はブラウザへ渡さない。

年月指定は `reflection_month = @month` を使い、取り込み日や推測した対象期間で代用しない。月全体の要約は全文取得と入力上限を扱い、top-k類似検索だけで網羅したとは扱わない。日本時間の月境界・欠損・省略を明示する。

ETL側ではSilver公開（[Issue #128](https://github.com/qei-2027-700/go-drive-etl/issues/128) / [PR #132](https://github.com/qei-2027-700/go-drive-etl/pull/132)）、文書単位Gold View（[Issue #129](https://github.com/qei-2027-700/go-drive-etl/issues/129) / [PR #136](https://github.com/qei-2027-700/go-drive-etl/pull/136)）の完了記録がある。専用サービスアカウントによる月検索・権限検証（[Issue #137](https://github.com/qei-2027-700/go-drive-etl/issues/137) / [PR #138](https://github.com/qei-2027-700/go-drive-etl/pull/138)）は2026年10月16日の記録で完了している。これはAWSアプリ実行基盤からの接続検証とは別。正確な対象期間の重複検索は [go-drive-etl #133](https://github.com/qei-2027-700/go-drive-etl/issues/133) の後続作業であり、年月ラベルの検索自体は妨げない。

## 個人データ・認可・削除

本人の私的記録は本人だけが読める利用から始める。公開デモは招待制を基本案とし、認証・認可と公開可能な自作の合成資料を使う。第三者へ展開する前に、文書・会話・出典の利用者ごとの分離を設計・検証する。共有サンプルのモデルを個人データ分離の実装済みモデルとは扱わない。

認証はaccess tokenの署名・発行元・期限・client・用途等に加え、現在の利用状態・権限・アプリ側の失効を確認する。画面だけで権限を制御せず、ID差し替え・旧管理者token・ログアウト後の利用を拒否する。

アップロードは形式・実内容・容量・抽出量を検証し、隔離領域と取り込む版の固定で差し替えを防ぐ。第三者の任意ファイルを受け入れる前にマルウェア検査等を決める。非同期処理では配送失敗の回復、重複・再送・同時生成の制御、有限の再試行を設計する。モデル呼び出しの結果不明時に自動再生成せず、二重課金を完全に防げるとは約束しない。

削除では新規検索・原文URL発行を止め、取り込み・生成との競合で復活や誤公開が起きないようにする。物理削除は保存先ごとに確認し、途中失敗を回復する。発行済み原文URLの最大2分という既存設計案、保存済みチャットの引用文、ログ・監査・バックアップの扱いを明示し、全保存先からの即時消去とは説明しない。保持期間の数値は未確定。

文書内の命令はデータとして扱う。捏造引用、Markdown/HTMLのXSS、危険URL・外部画像を検証する。通常ログへ文書本文・質問・回答・token・署名付きURLを出さず、外部追跡やモデル入出力ログは初期無効とする。IAMは責務ごとの最小権限、CIのAWS認証はOIDCを基本案とし、fork PRへ権限・secretを渡さない。

## 段階と未決事項

2026年10月末は、公開可能なサンプルの「検索 → 回答 → 出典確認」と画面またはAPIの代表操作を示す中間デモを目指す。約40%は目標の目安であり、現在の達成率や測定済み工数ではない。最終必須機能一式の完成と区別し、実AWS確認済み・fake・未実装を明示する。10月末以降も開発を継続する。

PostgreSQLは採用済み。配置先・ORM・テーブル設計、API実行基盤・配送、リージョン、生成・embeddingモデルと次元、今後導入する依存の版、予算・利用枠、MFA・招待方式・保持期間、ETL接続方式、中間デモの詳細は未決定。過去のLambda・DynamoDB・SQS等の構成案を採用済みとして扱わない。既存の数値・費用試算を承認済み予算や実測として扱わない。
