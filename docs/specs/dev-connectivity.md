# 開発用の接続テスト

[Issue #2](https://github.com/qei-2027-700/retrosprint-rag/issues/2) のローカル・CI向け機能。チャット、保存、ログイン、履歴取得は含めない。DB・AWSへの接続と認証情報を要求しない。

## 操作と契約

`/` で接続確認とechoを別々に実行する。healthは認証不要でHTTP応答だけを確認し、`status` は固定値 `ok`。echoは必須文字列の前後空白を除去し、1〜200文字を受け付けて除去後の値を返す。欠落、型違い、空白のみ、上限超過はFastAPI標準のdetail配列を持つ422とする。requestとresponseは別のPydanticモデルにする。

HTTP形式は [生成OpenAPI](../../frontend/openapi/openapi.json) を参照する。echoは `RETROSPRINT_ENABLE_DEV_API=true` のときだけ有効とし、既定は無効。契約生成では開発用APIを明示的に有効にする。

## 開発中の型更新

`mise run dev:be` の起動時と、backendの `src/`・`scripts/` 内のPythonコード変更後の再起動時に、既存の `api:generate` を実行する。生成に失敗したプロセスではAPIを起動せず、ターミナルにエラーを出す。修正後の保存で再試行できる。生成物は引き続きGit管理し、CIで生成差分を検出する。

## BEのCompose開発環境

[Issue #4](https://github.com/qei-2027-700/retrosprint-rag/issues/4) はBEだけをCompose化する。FEはホストで起動し、既存のHMRを利用する。Python・uvをホストへ導入せず、DockerとComposeからBEを起動できることを目的とする。FEの起動とTypeScript型生成には、引き続きホストのNode・pnpmを使う。

1. `.env.example` からBEの設定を用意し、`docker compose config` と `docker compose up --build` が成功する。
2. BEはコンテナ内の `0.0.0.0:8000` でlistenし、ホストには `127.0.0.1:8000` だけを公開する。`/health` と `/docs` は200、`/` は404となる。
3. 開発用echoの200・入力不正の422、ホストFEのoriginへのCORS許可、通信停止後の再起動・再送を確認する。echo無効時はルートとOpenAPIから除外する。
4. Pythonソース保存時にBEがリロードする。ホストの仮想環境・依存・キャッシュを共有せず、依存はlockfileからイメージへ導入する。
5. Compose経由でOpenAPI、ホストの既存FEコマンドでTypeScript型を生成でき、API未変更時に再生成差分が出ない。Composeでは起動・リロード時の自動生成を行わず、API変更後に明示的に生成する。

起動・ログ・停止・再ビルド・依存更新・型生成・環境変数は [Backend README](../../backend/README.md#docker-composeでbeを起動) に記載する。新しいcheckout相当での実行コマンド・結果・ログの場所を記録し、既存の共通検証とCIを維持する。FE用Dockerfile、FEコンテナ、コンテナ内のTypeScript型生成、本番用コンテナとAWSは対象外。

## 状態と画面

接続確認は未確認・確認中・成功・失敗を表示する。echoは未入力・送信中・成功・入力不正・HTTPエラー・通信失敗を扱い、入力不正と通信失敗を区別する。失敗後は入力を保持して修正・再送できる。

送信中は入力と送信ボタンを無効にし、通信処理でも重複を防ぐ。再送・入力変更時には前回の応答を消し、BEから返った値だけを応答として表示する。各リクエストは10秒でタイムアウトし、通信失敗として再送できる。

PCのサイドバーは上部メニューと独立スクロールするセッション領域を持ち、768px未満ではモーダルドロワーとする。メニューは接続テストだけ、履歴は空状態とする。ドロワーは背景・閉じるボタン・Escape・リンク選択で閉じる。開いている間はフォーカスを内部に留め、閉じたらメニューボタンへ戻す。

label、入力エラーの関連付け、状態の読み上げ、フォーカス表示を用意する。長いURL・連続文字列も折り返し、横スクロールを防ぐ。詳しい配置方針は [画面設計](../architecture/frontend-layout.md) を参照する。

## 受入条件

1. healthの200、echoの200・空白除去・境界値、入力不正の422、公開向け設定の404、CORSの許可・拒否を契約テストで確認する。
2. OpenAPIをサーバー起動なしで安定して生成でき、誤ったAPI利用を型検証で拒否する。生成済みファイルの変更と未追跡ファイルを差分チェックで検出する。
3. 320・390・768・1280pxのブラウザで実BEへ送信し、応答表示と横スクロールがないことを確認する。スマホ幅ではドロワーの閉じ方とフォーカス管理も確認する。
4. 静的生成物で実422、BE停止による通信失敗、再起動後の再送を確認する。通信中の重複防止と入力・応答の対応を単体テストで確認する。
5. 開発用BEを起動し、APIモデル変更後にOpenAPIとFEの型が更新され、生成失敗後も修正・保存で復旧できる。
6. lint・型・テスト・配布物ビルド・静的生成・生成差分・E2Eを、ローカルと通常CIで同じコマンドから実行する。

実機でのキーボード・縦横表示、スクリーンリーダー、実AWS、本番公開は未確認。自動E2Eの成功をこれらの検証済みとして扱わない。
