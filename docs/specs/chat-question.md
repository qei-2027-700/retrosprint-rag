[月の振り返り・関連検索](reflection-retrieval.md)の用途別fakeへ拡張済み。本書の代表質問と失敗ケースを維持し、追加の用途・年月・取得範囲は後続specを正本とする。

## 範囲・利用条件

公開可能な合成資料を使い、ローカルのNuxtからFastAPIへ単一の質問を送り、fakeによる回答と出典を確認する。検索・回答生成の契約とfake実装を分離し、外部サービスへの接続は行わない。画面に「合成資料を使ったデモ・回答はfake」と表示する。

認証・権限分離は未実装で、ローカル開発専用とする。私的記録・勤務先の内部資料を使わない。実AWS接続、実検索・モデルの品質評価、資料一覧・登録、複数ターン会話、履歴保存、DB永続化、本番公開は対象外。

## メニューと操作

| 表示名 | 今回の動作・扱い |
| --- | --- |
| 新しいチャット | 入力・質問・回答・出典・エラーを消して初期状態に戻す。送信中は操作できない |
| チャット履歴 | サイドバーの見出し。「履歴保存は未対応」と表示し、架空の履歴は置かない |
| 資料一覧 | 後続機能。今回はメニューに表示しない |
| ログアウト | 認証実装時に追加。今回は表示しない |

管理者用の「資料を追加」は後続の資料一覧画面に置く。既存の「接続テスト」は開発用の別画面として残し、チャット本文にhealth・echoの操作を混在させない。チャットは `/`、接続テストは `/dev/connectivity` とし、サイドバー下部の「接続テスト（開発用）」から開く。

## PC・SPの配置

PC（768px以上）は左に幅260px程度のサイドバー、右にメイン領域を配置する。サイドバー上部にメニュー、その下にチャット履歴の領域を置く。メイン領域は上部に画面タイトルとfakeの表示、中央に質問・回答・出典のテキスト、下部に質問入力と「送信」を置く。本文と入力欄の最大幅を揃え、長い回答は本文領域で縦にスクロールする。入力欄が最後の回答・出典を覆わないようにする。

SP（768px未満）は上部にメニューボタンと画面タイトル、中央に本文、下部に質問入力と送信を置く。サイドバーは左から開くモーダルドロワーとし、メニュー名と並びはPCと同じにする。背景・閉じるボタン・Escape・メニュー選択で閉じ、開いている間はフォーカスを内部に留め、閉じたら起点へ戻す。

動的な画面高とsafe areaを考慮する。ソフトウェアキーボード表示時も入力・送信・本文にアクセスできるようにし、長文・引用・URLは折り返して横スクロールを防ぐ。入力文字は16px以上、主要操作の高さは44px以上を設計目標とする。

## 質問・回答・出典の動作

1. 質問前は利用案内と代表質問を表示する。入力にはlabelを付け、送信ボタンで送信する。Enterは改行として扱う。
2. 送信開始時に前回の結果を消し、送信した質問と回答待ちの表示を出す。入力・送信・新しいチャットを無効にし、通信処理でも重複送信を防ぐ。
3. 成功時は送信した質問、回答、対応する出典を表示する。各質問は独立して処理し、過去の質問・回答をAPIへ渡さない。次の質問の送信時に表示を置き換える。
4. 出典は回答の下に文書名と引用を表示し、「出典を確認」で文書ID・版・見出しまたはページ・根拠箇所を確認できる。PC・SPとも回答下の開閉領域を使い、同じ合成原文と照合できるようにする。
5. 「新しいチャット」で表示と入力を初期化する。ページ再読み込みでも初期状態となり、保存・履歴再開は行わない。

回答と引用はテキストとして表示し、HTMLを実行しない。出典にリンクを付ける場合は許可するURL形式を定義する。通常ログへ資料本文・質問・回答を出力しない。

## 状態・エラー・制限

| 状態 | 表示と復帰操作 |
| --- | --- |
| 質問前 | 案内・代表質問・入力欄 |
| 回答待ち | 処理中であることを表示し、状態を読み上げる |
| 回答あり | 質問・回答・出典を表示する |
| 根拠不足 | 根拠が見つからない旨を表示する。根拠のない回答・引用は返さない |
| 入力不正 | 空白のみ・上限超過などを入力欄に関連付けて表示し、修正できる |
| fakeの処理失敗 | 処理に失敗した旨を表示し、入力を保持して再送できる |
| 通信失敗・タイムアウト | 接続を確認して再送する案内を表示し、入力を保持する |

前後空白を除去した質問を検証する。根拠不足と処理失敗を区別し、入力不正・失敗を成功した回答として表示しない。エラー後は入力と送信を再び有効にする。送信開始時と新しいチャットの操作時に古いエラーを消す。

## API契約と再現方法

FastAPIで質問・回答・出典・根拠不足の契約を定義し、OpenAPIからTypeScript型を生成する。FEは既存HTTPクライアントと生成型を使い、HTTP契約を手書きで重複定義しない。

`POST /api/questions` に `{ "question": "質問文" }` を送る。質問は前後空白を除去して1〜2,000文字とし、文字列以外・欠落・空白のみ・上限超過を422で拒否する。FEのタイムアウトは65秒とする。

200の応答は `status` で区別する。`answered` は `answer.text`、`answer.citation_ids`、`citations` を返す。`insufficient_evidence` は `answer: null`、`citations: []` を返す。どちらも `mode: fake` を含む。出典は `id`、`document_id`、`document_name`、`content_version`、`reflection_month`、`heading`、`page`、`quote`、`original_text` を持つ。回答の `citation_ids` を出典の `id` に対応づけ、版を固定した合成原文を応答に含めて引用と照合する。

fakeの処理失敗は500で `code: question_processing_failed` と表示用の `message` を返す。入力不正はFastAPI標準の422 detail配列とする。APIは `RETROSPRINT_ENABLE_DEV_API=true` のときだけ有効で、既定ではルートとOpenAPIから除外する。既存のCORS設定を使う。

| 質問（前後空白除去後） | 再現結果 |
| --- | --- |
| 最近うまくいったことは？ | 回答あり。2026年9月の合成振り返りを出典として返す |
| 処理失敗の確認 | fakeの処理失敗（500） |
| その他の有効な質問 | 根拠不足（200） |

検索・回答生成は固定結果を返すfakeであり、意味検索を行わない。通信失敗はBEを停止して確認し、再起動後に同じ入力を再送する。

## 受入条件

1. AWSアカウント・DB・外部APIキーなしでホストFEとComposeまたはホストBEを起動し、実BE経由で質問・回答・出典確認ができる。引用を合成原文と照合できる。
2. 回答あり・根拠不足・入力不正・処理失敗・通信失敗を再現でき、失敗後の入力保持・修正・再送、重複送信防止、新しいチャットの初期化が動作する。
3. 320・390・768・1280pxで主要操作、本文・出典の折り返し、下部入力と本文の重なりがないことを確認する。SPのドロワー開閉・フォーカス管理と、長い回答・引用のスクロールを確認する。
4. PC・SPともfake利用と履歴未対応が分かり、未実装機能を操作できるように見せない。HTMLが実行されず、通常ログに資料本文・質問・回答を出さない。
5. API契約・fakeのケース・主要画面操作を検証し、生成型を更新して `mise run check` が成功する。代表質問・再現方法・検証結果・制限を記録する。

SP実機のキーボード・縦横表示は自動E2Eと分けて確認結果を残す。未確認の場合は明記する。fakeの成功を実RAGの品質・費用・速度や認証認可の検証済みとして扱わない。
